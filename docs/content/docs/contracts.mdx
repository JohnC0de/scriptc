---
title: "Contract Types"
---

Contract types are type aliases that mean nothing to TypeScript or Node.js but are promises scriptc checks. You import them from `@scriptc/types` with `import type`, which TypeScript erases, so Node.js never loads the package and runs the program exactly as without the annotations. scriptc proves each contract or rejects the program with a diagnostic that explains why the contract does not hold. A program that compiles behaves exactly as under Node.js; the contract only adds an optimization that scriptc can now rely on.

Add `@scriptc/types` to your project's development dependencies. It contains only type declarations.

## Example

```ts:main.ts
import type { Immutable, Int32, NoThrow } from "@scriptc/types";

const KEYWORDS: Immutable<Map<string, number>> = new Map([
  ["const", 1],
  ["let", 2],
  ["function", 3],
]);

class Token {
  pos: Int32;
  end: Int32;
  kind: number;
  constructor(pos: Int32, end: Int32, kind: number) {
    this.pos = pos;
    this.end = end;
    this.kind = kind;
  }
}

function isLetter(ch: number): NoThrow<boolean> {
  return (ch >= 97 && ch <= 122) || (ch >= 65 && ch <= 90);
}

function scan(text: string): Token[] {
  const tokens: Token[] = [];
  let pos: Int32 = 0;
  while (pos < text.length) {
    if (!isLetter(text.charCodeAt(pos))) {
      pos = (pos + 1) | 0;
      continue;
    }
    let end: Int32 = pos;
    while (end < text.length && isLetter(text.charCodeAt(end))) end = (end + 1) | 0;
    tokens.push(new Token(pos, end, KEYWORDS.get(text.slice(pos, end)) ?? 0));
    pos = end;
  }
  return tokens;
}

for (const t of scan("const answer = 42; function f() {}")) console.log(t.pos, t.end, t.kind);
```

Node.js 24 runs the program directly:

```console
$ node main.ts
0 5 1
6 12 0
19 27 3
28 29 0
```

The scriptc executable prints the same output. `KEYWORDS` is immortal, `Token.pos`, `Token.end` and the scanner's positions are 32-bit integers, and the calls to `isLetter` carry no exception checks:

```console
$ scriptc build main.ts -o scan >/dev/null
$ ./scan
0 5 1
6 12 0
19 27 3
28 29 0
```

## Where contracts apply

scriptc recognizes a contract where it is written as the annotation of a declaration, and only when the name is imported from `@scriptc/types` (a named import, possibly renamed, or a namespace import such as `sc.Int32`). TypeScript does not keep alias names in inferred types, so a contract never spreads by inference: write it where the value is declared.

<dl>
  <dt><code>NoThrow&lt;T&gt;</code></dt>
  <dd>The written return type of a function, method or arrow function. <code>NoThrow&lt;Int32&gt;</code> and <code>NoThrow&lt;Immutable&lt;T&gt;&gt;</code> combine the result contracts.</dd>
  <dt><code>Int32</code></dt>
  <dd>Parameters, variables, class instance fields and function results whose type is a plain <code>number</code>.</dd>
  <dt><code>Immutable&lt;T&gt;</code></dt>
  <dd>Parameters, variables, class instance fields and function results.</dd>
</dl>

A contract anywhere else (a type alias, an interface member, an element or type argument such as `Int32[]`, a function type) would promise something scriptc does not check, so the build reports it with SC7006.

## NoThrow

A `NoThrow` function must not contain a path to a throwing operation: a `throw`, a call to a function that may throw, a call through a function value that may hold such a function, an operation that throws in Node.js (such as reading a property of `undefined`), or recursion, whose stack guard can throw `RangeError`. scriptc already computes this for every function to omit exception checks; the contract turns the result into a guarantee and reports the first throwing path when it does not hold.

A `try` statement discharges what its handlers take. A throwing call inside a `try` with a `catch`, or inside a `try` whose `finally` always ends with `return`, `break` or `continue` (which discards the pending exception), cannot leave the function:

```ts:digits.ts
import type { NoThrow } from "@scriptc/types";

function parseDigit(ch: number): number {
  if (ch < 48 || ch > 57) throw new RangeError("not a digit");
  return ch - 48;
}

function digitOr(text: string, i: number, fallback: number): NoThrow<number> {
  try {
    return parseDigit(text.charCodeAt(i));
  } catch {
    return fallback;
  }
}

console.log(digitOr("7", 0, -1), digitOr("x", 0, -1));
```

```console
$ node digits.ts
7 -1
$ scriptc build digits.ts -o digits >/dev/null
$ ./digits
7 -1
```

The `catch` and `finally` bodies are checked like any other code: a rethrow, a throwing call in the `catch`, or a `try`/`finally` without `catch` whose `finally` can complete normally (and so re-raises the exception) still fails the contract. A recursive function cannot be `NoThrow`, because its stack guard throws on entry, outside any handler. In programs that use worker threads, `try` does not discharge the contract, since a termination request unwinds through `catch`. `async` functions and generators cannot be `NoThrow`.

## Int32

Each value stored into an `Int32` slot (initializers, assignments, compound assignments, `++` and `--`, arguments and returns) must be an int32 in Node.js semantics, so storing it as a 32-bit integer cannot change it:

- an integer literal in range;
- the result of `|`, `&`, `^`, `~`, `<<`, `>>` or `Math.imul`;
- another `Int32` value;
- arithmetic whose range scriptc can bound, such as `i + 1` under a loop condition `i < text.length`.

`x >>> 0` is a uint32 and is not accepted. Anything else needs an explicit `| 0`, which makes Node.js compute the same 32-bit value. Reads keep JavaScript semantics: `a + b` of two `Int32` values is an ordinary number that may exceed the int32 range.

scriptc refuses an `Int32` slot whose writes it cannot all see (SC7003): a parameter of a function used as a value, or a field of a class whose instances reach `any` or dynamic code.

## Immutable

`Immutable<T>` is a deep read-only view, so TypeScript already rejects direct writes such as `KEYWORDS.set(...)`. scriptc also checks the writes TypeScript cannot see:

- a method that writes `this`, called on the value;
- a function that writes a parameter, given the value;
- a cast such as `value as number[]`, an `any` alias, `Object.assign`, or index-signature writes;
- a value stored into an `Immutable` slot that another reference can still change.

A value stored into an `Immutable` slot must be fresh: a literal, a `new` expression whose constructor keeps `this` to itself, or a function that returns what it builds. Values that reach dynamic code, or functions scriptc cannot see, are refused.

## Diagnostics

Each failed contract names the declaration and the reason:

```ts:reject.ts
import type { Immutable, Int32, NoThrow } from "@scriptc/types";

const LIMITS: Immutable<number[]> = [10, 20];

function widen(limits: number[]): void {
  limits.push(30);
}

function parseDigit(ch: number): number {
  if (ch < 48 || ch > 57) throw new RangeError("not a digit");
  return ch - 48;
}

function digitAt(text: string, i: number): NoThrow<number> {
  return parseDigit(text.charCodeAt(i));
}

function middle(start: Int32, end: Int32): Int32 {
  return (start + end) / 2;
}

widen(LIMITS as number[]);
console.log(digitAt("7", 0), middle(2, 5), LIMITS.length);
```
