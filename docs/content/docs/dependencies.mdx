scriptc compiles eligible npm dependencies to native code alongside your application. Package support is partial: unsupported packages and operations receive diagnostics, and there is no runtime JavaScript engine fallback.

## Use a package

Create `tool.ts`:

```ts:tool.ts
import { Command } from "commander";

const program = new Command();

program
  .name("greet")
  .argument("<name>", "who to greet")
  .option("-u, --upper", "use uppercase")
  .action((name: string, opts: { upper?: boolean }) => {
    const text = `hello, ${name}`;
    console.log(opts.upper ? text.toUpperCase() : text);
  });

program.parse();
```

Install the dependency, then build and run the executable:

```console
$ npm install commander
$ scriptc build tool.ts -o greet >/dev/null
$ ./greet ada --upper
HELLO, ADA
```

Both the callback and the package implementation compile to native instructions. Use [coverage reports](/docs/coverage) to inspect package compilation and deferred operations.

## Package resolution

The compiler resolves dependencies from `node_modules` using Node.js package resolution, including `package.json` export conditions. It recursively compiles eligible dependencies. The executable does not load `node_modules` at runtime.

Automatic selection requires readable runtime source and a package-owned declaration surface. Packages that fail eligibility or preflight receive a package-specific diagnostic. TypeScript workspace entries compile as program modules, including `.js` specifiers that resolve to `.ts` sources.

## Explicit package selection

`--npm-static <pkg[,pkg…]|auto>` remains available for explicit selection. Naming a package overrides the automatic declaration-surface eligibility check, allowing an attempt to compile packages that rely on separately installed declarations or inferred JavaScript types. `auto` uses the default automatic selection. Neither form bypasses compilation checks.

An accepted package may contain deferred operations: the build succeeds and coverage lists those sites, but executing an unsupported deferred operation raises a runtime error. Review the coverage report and test the paths your application uses. See [Limitations](/docs/limitations) for native runtime differences.

## Provenance sources (experimental)

`--provenance-sources` attempts to compile a package from source at its npm provenance-attested commit. This allows TypeScript source to compile as TypeScript instead of compiling the published JavaScript. Packages without usable attestations keep their installed-source compilation path, subject to the same native eligibility and compilation checks.
